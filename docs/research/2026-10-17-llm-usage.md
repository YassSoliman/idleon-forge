# Where a cheap or free LLM helps, and how to spend few tokens (2026-10-17)

Ticket: [#17](https://github.com/YassSoliman/idleon-forge/issues/17). Blocks #13 (MVP feature cut) and #14 (architecture).

Method: I started from the awesome-list (`open-free-llm-api/awesome-freellm-apis`, README pushed 2026-10-17), then checked every number and term below on the provider's **own** current docs, legal pages or pricing pages, fetched on 2026-10-17. I did not sign up for anything or use any API key. Free tiers change often, so each claim is only as good as its fetch date. Confidence: **H** = read on the provider's own page, **M** = provider page was vague or partly rendered, **L** = secondary source only.

## Answer

- **Adopt offline rule mining (use 1) now, in the MVP, with no runtime LLM.** It fits [ADR 0002](../adr/0002-deterministic-advice-ai-built-knowledge.md) as written. Run it with the agents we already use (Claude Code on Yasser's existing plan), so it adds no provider, no key and no new cost. A human reviews every output into the Knowledge Base, with a Source and a patch.
- **Add one more offline use to the MVP: a patch-note staleness pass.** When a patch lands, an LLM reads the patch notes against the Knowledge Base and lists the entries that may now be Stale, plus new Goal candidates. This is the cheapest high-value use: small input, and it targets the exact failure ADR 0004 exists for.
- **Defer the "Ask why" side chat (use 2) until after the MVP.** It needs an ADR 0002 amendment and a Worker holding a key. That contradicts the hosting decision ([#6](https://github.com/YassSoliman/idleon-forge/issues/6): no Worker code in the MVP), and the MVP success bar is the Now screen alone.
- **Do not use an LLM for ranking, Verdicts, Next Action text or "why" lines.** Deterministic templates over the Knowledge Base already give the one-line why, and they never hallucinate.
- **When "Ask why" ships, the first-choice provider is Cloudflare Workers AI** (`@cf/openai/gpt-oss-120b`) through a Worker binding. It is on the account we already pay for, needs no key in the browser, Cloudflare does not train on the content, and 10,000 free Neurons/day cover about 60 questions a day. Past that, each question costs about $0.002. (H)
- **The fallback is Groq** (`openai/gpt-oss-120b`, behind the same Worker). Its free plan gives 30 RPM and 1K RPD. Its contract bars training on inputs and outputs, and it enforces strict JSON-schema output. (H) For the public future, add **OpenRouter bring-your-own-key** via OAuth PKCE: the browser gets the user's own key, with no secret of ours. (H)
- **Avoid Gemini's free tier for anything that sees a save.** Google's terms say "Do not submit ... personal information to the Unpaid Services", free-tier content is used to improve Google products and human reviewers may read it, and free-tier API clients may not serve users in the EEA, UK or Switzerland. (H) Also avoid Mistral's free tier (it reportedly trains on data, and I could not verify that on Mistral's own pages; L), Cerebras (now a 30-day, $5 trial, not a permanent free tier; H) and GitHub Models (fully retired 2026-07-30; H).
- **Token rule: never send a raw save.** Our fixtures are ~0.3 MB raw and ~4.6–4.9 MB parsed (roughly 100k and 1.5M tokens). "Ask why" must send a small per-question slice: the one Goal, its Next Action, the Knowledge Base entries it cites, and the few Account State fields they read. That keeps a question to about 2–4k tokens. Use a 20B model first, cache answers by (Knowledge Base version, slice hash), and enforce JSON output.
- **Treat every free tier as disposable.** Within this one check, the list labels Cerebras "permanent free" while Cerebras's own page says trial, and GitHub Models has vanished. So put the provider behind a single adapter with a fallback chain, and make sure the app works fully with the LLM off.

## 1. Which uses are worth it

| Use | Fits ADR 0002? | Value | Token cost | Verdict |
|---|---|---|---|---|
| **Offline rule mining**: propose Goal links, Milestones, activity-to-Goal links and non-obvious correlations from the Knowledge Base, guides and our two Account States; a human reviews them into the Knowledge Base | Yes, as written ("AI agents do the research that fills the Knowledge Base") | High: it is how the Knowledge Base gets built at all | One-off, batchable, no latency need | **Adopt, MVP** |
| **Patch-note staleness pass**: diff new patch notes against Knowledge Base entries, flag Stale candidates and new mechanics | Yes (offline, human-reviewed) | High: the game patches every 1–2 weeks, and ADR 0004 exists because old mechanics keep their names | Small: patch notes plus entry titles | **Adopt, MVP** (manual run per patch) |
| **Source extraction**: turn a guide, wiki table or Reddit post into draft Knowledge Base entries with Source, date and patch filled in | Yes | High; this is the bulk of the mining work | Medium per source, one-off | **Adopt, MVP** (part of mining) |
| **kb-correction issue triage**: match a "Report this" GitHub issue to the Knowledge Base entry it disputes | Yes (offline) | Medium, and only once there are many users | Small | Later |
| **"Ask why" side chat**, grounded on Account State plus the Knowledge Base, labelled, never changing the ranking | **No**: needs an amendment ("no LLM runs at advice time") | Medium: the Next Action already carries a one-line why and a Source link | Per question, ongoing | **Later**, behind a flag, after the MVP |
| LLM-written Next Action text or "why" lines | No | Low: templates do it deterministically | Ongoing | **Reject** |
| LLM ranking, Verdicts or Leverage | No | Negative: inconsistent and stale-prone, which is the reason for ADR 0002 | Ongoing | **Reject** |

Why "Ask why" is not MVP: the MVP bar (map #1) is playing 5 sessions "using only ActiveOn's Now screen, never asking Google or an AI chat". A side chat would be the very thing the bar tests against. It also forces a Worker plus key management, and #6 settled on no Worker code. If it is built later, the ADR 0002 amendment should say: the chat may only explain items already on the Now screen, it cites the same Sources, it is visibly labelled, and nothing it says feeds back into ranking.

**Provider for the offline uses.** Mining and the staleness pass run in agent sessions (Claude Code), as all research in this repo already does. That needs no free API. Privacy note: Anthropic consumer plans use "chats and coding sessions" for training only if the user enabled the model-improvement setting, so Yasser should check that setting before feeding in Joseph's save (H, [privacy.claude.com](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)). Joseph has already shared the save as a fixture, but it is still personal data.

### Quality for structured reasoning

No provider page measures quality on our task, so treat this as a judgement. The safe pattern is a model that can be **forced** into a JSON schema: Groq's strict mode guarantees conformance, while Workers AI's JSON mode is best-effort. A mid-size open-weight reasoning model (gpt-oss-120b, available on both) is enough for "explain this cited fact in context". That is not the kind of open-ended game reasoning ADR 0002 rejected. For mining, where quality matters most and latency matters least, use the strongest model we have (the agent session), not a free tier.

**Budget arithmetic** (Workers AI gpt-oss-120b: 31,818 Neurons per M input tokens, 68,182 per M output tokens; H, [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)). A 4k-token-in, 500-token-out question costs ≈ 127 + 34 ≈ 161 Neurons, so 10,000 free Neurons ≈ 60 questions/day. Past that, 161 Neurons ≈ $0.0018 per question. gpt-oss-20b is cheaper still.

## 3. Token-minimizing techniques

1. **Never send a raw or parsed save.** Fixture sizes: raw 307 KB and 364 KB, parsed 4.6 MB and 4.9 MB, measured locally on `fixtures/private/` (content not read). The parsed output alone is ~1.5M tokens, far past any free tier.
2. **Send a per-question slice:** the Goal, its Next Action and Verdict, the cited Knowledge Base entries (text plus Source plus patch), and only the Account State fields those entries read. The engine already knows which fields it read, so it can emit the slice deterministically.
3. **For mining, send diffs and summaries:** the change between two saves (what moved in a Play Session), Knowledge Base entry titles plus IDs instead of full bodies, and the patch-notes text instead of whole wiki pages.
4. **Cache:** key on (Knowledge Base version, slice hash, question template). Most "why" questions repeat across sessions and between our two accounts.
5. **Small model first:** gpt-oss-20b for explanations, escalating to 120b only on schema failure or a low-confidence flag.
6. **Fixed short output:** JSON with `answer` (≤ 80 words) and `cites[]` (Knowledge Base IDs only), and `max_tokens` capped. Reject any answer that cites an ID not in the slice.
7. **Canned questions over free text:** "Why this Next Action?", "Why not the Higher-leverage option?", "What changes after this Milestone?". This makes caching effective and keeps prompts small.
8. **Abuse limits** (once public): a per-user daily cap in the Worker, plus Workers AI's own per-minute limits, and BYOK for heavy users.

## 4. Provider plan and fallbacks (for when "Ask why" ships)

1. Worker → **Workers AI** `@cf/openai/gpt-oss-20b`, escalating to `gpt-oss-120b`. No key leaves the server, no training, already-paid account.
2. On error or quota → **Groq** `openai/gpt-oss-120b` with strict `json_schema`; key in a Worker secret; ZDR turned on.
3. Public users who want more → **OpenRouter BYOK** via PKCE, with the "don't route to providers that train" setting explained to the user.
4. LLM off → the app is unchanged. "Ask why" just hides.

Never: Gemini free tier with a save in the prompt (its terms forbid personal data, it trains, it has an EEA/UK block); a key in the client bundle.

## Flags for later tickets

- **#14 (architecture):** keep the MVP client-only as #6 decided. If "Ask why" is planned, reserve a `/api/ask` Worker route and a provider adapter interface now, so adding it later is not a rewrite. The advice engine should expose "which Account State fields and Knowledge Base IDs produced this Next Action", which is needed for slicing and useful for debugging anyway.
- **#13 (feature cut):** offline mining and the patch-note staleness pass are tooling (scripts and agent procedures in the repo), not user-facing features. "Ask why" is out of the MVP.
