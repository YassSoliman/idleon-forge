# Is an always-on-top overlay possible and allowed?

Research for [#8](https://github.com/YassSoliman/idleon-forge/issues/8), part of the ActiveOn MVP map ([#1](https://github.com/YassSoliman/idleon-forge/issues/1)). Researched 2026-10-16. Confidence: H = primary source read, M = secondary or inferred, L = unverified.

## Answer

- **Possible: yes, four ways, none of which touch the game client.** An overlay here is just a separate window that ActiveOn draws above IdleOn; it never reads the game's memory, injects code or sends input, so it stays a read-only Mod. (H for each API, below)
- **Cheapest: the Document Picture-in-Picture API.** The hosted ActiveOn web app can pop its Now screen into an always-on-top window. It needs no install, works in Chrome/Edge 116+, needs one click (a user gesture), and closes when the opener tab closes. Safari has no support. (H)
- **Steam players get one for free.** The Steam overlay (Shift+Tab) has a built-in web browser, and since the 14 June 2023 client update overlay panels can be "pinned" with adjustable opacity over the running game. Joseph could pin the hosted ActiveOn URL there. Whether IdleOn's Steam build supports the overlay, and whether Firebase/Steam login works inside it, is **untested**. (H for pinning, M for the browser being pinnable, L for IdleOn)
- **Electron or Tauri** give a true always-on-top desktop panel (`setAlwaysOnTop`, plus `visibleOnFullScreen` on macOS), but they add a packaged desktop app to build, sign and update. Not worth it while PiP and the Steam overlay exist. (H)
- **A plain browser window or an installed PWA cannot pin itself on top.** There is no web API for that outside Document PiP; the user would need an OS tool (e.g. PowerToys "Always on Top"). (M)
- **Allowed by Steam: yes.** The Steam Subscriber Agreement (updated 10 Sep 2026) forbids Cheats, tampering with the execution of Steam or Content, and scripts/bots/macros that interact with Content. A separate read-only window does none of these, and the Steam overlay browser is Valve's own feature. (H for the text, M for the reading)
- **Allowed by LavaFlame2: tolerated, never endorsed.** No ToS or third-party-tool policy is published. The only developer statement found is about a desktop overlay for the fishing minigame (IdleonHelper, 2021): "looks cheatery", "its not like the games gonna ban you". Enforcement that does exist targets automation (a user reports a Discord ban for admitting to an auto-clicker, 2025). An advice panel that draws nothing over the game's own UI is lower-risk than that fishing overlay. (H screenshot; M for the rest)
- **Recommendation: keep the overlay as fog, not ruled out.** If ever wanted, the path is "Pop out" via Document PiP in the web app, plus a doc note for Steam users on pinning the Steam overlay browser. No desktop shell. Nothing in the MVP needs to change for this, except keeping the Now screen usable at a small window size.

## Details

### Options

| Option | What it needs | Always on top? | Notes | Conf. |
|---|---|---|---|---|
| Document Picture-in-Picture (web) | HTTPS, a click handler calling `documentPictureInPicture.requestWindow({width,height})`, then moving the Now screen's DOM into the PiP window | Yes ("floats on top of other windows") | Chrome/Edge 116+; Chrome docs also list Firefox 151+; Safari none. MDN still marks it experimental, not Baseline (page modified 2026-08-21). Size may be clamped by the browser. Dies with the opener tab. | H |
| Steam overlay web browser, pinned | Steam client with the overlay enabled for IdleOn; open the browser in Shift+Tab, load the ActiveOn URL, pin it | Yes, inside the game's overlay, with adjustable opacity | Pinning shipped in the 14 Jun 2023 client update. Secondary coverage says the web browser is among the pinnable panels. Unverified for IdleOn, and the Steam login copy-paste flow (see ecosystem note) may be awkward inside it. Steam-only, so no help for Yasser on Google login unless he plays the Steam build. | H / M / L |
| Electron `BrowserWindow.setAlwaysOnTop(true, level)` | A packaged desktop app; levels from `floating` to `screen-saver`; `setVisibleOnAllWorkspaces(true, {visibleOnFullScreen:true})` to show over macOS full-screen apps | Yes | Not supported on Wayland. Adds signing, auto-update, a second deploy target. | H |
| Tauri `setAlwaysOnTop` / `alwaysOnTop` config | A Tauri app; the permission `core:window:allow-set-always-on-top` (not in the default set) | Yes | Smaller binaries than Electron, same distribution cost. | H |
| Plain browser window or installed PWA | Nothing | No | No web API pins a normal window or PWA window on top. Chromium once floated an "always-on-top window" idea; it became Document PiP. Users can use an OS tool instead. | M |

Caveat for every desktop option: an always-on-top window cannot sit over an exclusive-fullscreen game on Windows. IdleOn's Steam build is commonly run windowed (IdleonHelper exists to save and restore its window size and position), so this is probably fine. Not verified on the current patch. (M)

### Developer and community statements

- **LavaFlame2, 2021 (Discord screenshot kept in se7enek/IdleonHelper as `LavaFlame2_Statement.png`):** about a fishing-minigame overlay: "that looks cheatery but i doubt itll really help that much", "its not like the games gonna ban you", "you dont get to feel like you earned it". IdleonHelper is an AutoHotkey tray app that draws PNG overlays on the game window and does not automate input. The repo was last pushed 2025-06-03. The statement is five years old and older than the current patch, so it is **possibly outdated**. (H, as viewed in the ecosystem research)
- **No published ToS or tool policy.** legendsofidleon.com has only a privacy policy and licenses page (see [ecosystem research §4](2026-10-16-ecosystem.md)). (H)
- **Automation is what draws enforcement.** In a Steam discussion from 10 Mar 2025, a user reports being "banned from the discord for admitting" auto-clicker use. Players there believe Lava detects odd progression, not local programs. This is community claims only, with no developer reply. (M)
- **Steam Subscriber Agreement, last updated 10 Sep 2026, §4.B–D:** "You agree that you will not create Cheats or assist third parties in any way to create or use Cheats"; "will not tamper with the execution of Steam or Content and Services unless otherwise authorized by Valve"; "You may not use any form of scripts, bots, macros, or other non-human-controlled systems to interact with Content and Services". A separate advice window falls under none of these. (H)

### What a later decision ticket must know

- The overlay question does not change the architecture: it is a presentation mode of the same hosted web app. The only requirement to carry into the MVP is "the Now screen works in a narrow window of about 400 px".
- Never draw over the game's own UI, and never read the screen or send input. That is the line between a companion and the "cheatery" overlay Lava commented on, and the line the Steam SSA draws at automation.
