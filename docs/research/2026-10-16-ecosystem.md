## 2. Where Toolbox's static game data comes from

- `data/website-data/*.json` (31 files, 8.9 MB) is headed **"Auto-generated by z-processing. Do not edit."** `z-processing` (with `tools/typeGenerator.js` and `process.js`) is referenced in CLAUDE.md, parsers/types.ts, classDefinitions.ts and others. It reads the game's own code and tables ("z-processing reads it out of the game's own..."; "section/VM extractor ... only evaluates data functions"). **z-processing is not in the public repo.** It appears to be a private sibling. **No separate public game-data package exists for Toolbox.** (H for the file headers, M for "private")
- Toolbox also builds an entity graph at prebuild time (`scripts/entity-graph/game-constants.mjs`, `build.mjs`).
- Idleon Efficiency gets its data from **BigCoight's IdleonWikiBot** (the bot behind the IdleOn wiki): `cp -r ../IdleonWikiBot/exported/ts/* data/domain/` produces `data/domain/{data,enum,model}` (195 `*Repo.ts` files). The public `BigCoight/IdleonWikiBot3.0` repo has **no license** and was last pushed **2025-04-02**, so it is stale relative to the W7 content. (H)
- Older or abandoned options: `Corbeno/idleon-data` (no license, last push 2022-01), and `desophos/idleon-saver` (MPL-2.0, last push 2022-03; Steam local-save ↔ JSON, with idleon-data and IdleonWikiBot3.0 as submodules). (H)

## 4. LavaFlame2 ToS / developer stance

- **No published ToS or third-party-tool policy found.** legendsofidleon.com links only to `/privacypolicy/` and `/licenses/`, and `/terms`, `/tos` and `/terms-of-service` return 404. The privacy policy has no clause on third-party tools. (H)
- The only primary-source developer statement found is a 2021 Discord screenshot about a **fishing-minigame overlay**, kept in github.com/se7enek/IdleonHelper (`LavaFlame2_Statement.png`). Lava said: "that looks cheatery but i doubt itll really help that much", "its not like the games gonna ban you", "you dont get to feel like you earned it". That is tolerance, not endorsement, and it is not about save reading. (H for the screenshot, which I viewed)
- In practice, read-only save tools are de facto tolerated: Toolbox and Efficiency have run for 4+ years, they are listed on the community wiki's External Resources page, and they call Lava's own cloud functions (`asil`, `tspa`, `capsc`, `xapsi`). **Risk:** every tool impersonates Lava's OAuth clients (Toolbox even ships the Google client secret). Lava could rotate these or add App Check at any time and break all of them. A web-search summary claiming "ToS prohibits third-party tools" pointed to another game's support page and is **not credible**. (M)

## 5. Existing "next action" / proactive coaching

- **Toolbox dashboard**: timers, "actionable alerts and reminders" (README), and a configurable tracker engine in `utility/dashboard/`. It only works **in-page**: I found no Web Notifications, Push, or service-worker code. (H)
- **Efficiency**: an `alerts.tsx` alert set, also in-page. (H)
- **AutoReview**: a prioritised per-system to-do/advice list. This is the closest match to "what should I do next," but it is a snapshot review aimed at long-term progression, not live play. (H)
- **ha-idleon**: real push notifications via Home Assistant attention sensors, with polling. It needs an HA install. (H)
- **The gap:** I found no tool that combines **realtime save sync (onSnapshot) + a ranked "do this now" queue for an active session + push notifications** in a standalone way.
