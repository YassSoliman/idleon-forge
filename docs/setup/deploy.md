# Deploying ActiveOn

ActiveOn is an assets-only Cloudflare Worker: `apps/activeon/dist/` served as static assets in SPA
mode ([`apps/activeon/wrangler.jsonc`](../../apps/activeon/wrangler.jsonc)). No Worker script, no
bindings, no runtime secrets. It lives on the Forge's own Cloudflare account **IdleOn**, subdomain
`idleon`. The design is [M12](../specs/M12-release.md); the runbooks are in [`release.md`](release.md).

| What | Where |
|---|---|
| Production | `https://activeon.idleon.workers.dev`, deployed by [`deploy.yml`](../../.github/workflows/deploy.yml) on every push to `main` |
| Previews | `https://pr-<N>-activeon.idleon.workers.dev`, one per same-repo PR, by [`preview.yml`](../../.github/workflows/preview.yml), deleted on close, behind Cloudflare Access |
| Build stamp | `/version.json` (BuildInfo, M12 TR-4) and `/whats-new.json` (TR-7), generated by `packages/release` during `vite build` |

## How a deploy runs

`deploy.yml` has two jobs, both in the GitHub **production** environment (main only, no admin bypass):

1. **build**: lint, typecheck, test, `pnpm build` with `VITE_DEPLOY_CHANNEL=production` and the
   `VITE_*` values, the budgets, then uploads `dist/`. It never names the Cloudflare token.
2. **deploy**: checks out the same commit, refuses a `build` key in `wrangler.jsonc`, installs with
   `--ignore-scripts`, downloads `dist/`, runs `pnpm exec wrangler deploy`, then the smoke check:
   `/version.json` must show the deployed commit within 60 s and `/some/deep/link` must return 200 HTML.

If any step fails, the previous version stays live and the run is red. Never connect Cloudflare
Workers Builds to this Worker: it would be a second deploy path outside the GitHub gates.

## Suggestions (M13)

The app sends in-app Suggestions to the **Suggestions Worker** `activeon-suggestions`
([`workers/suggestions/`](../../workers/suggestions/)), a separate Worker on the same account, deployed
by hand with `wrangler deploy` (never from a Preview). The app needs two public build values, set as
GitHub environment **variables** in both `production` and `preview`, and in `apps/activeon/.env.local`
for local builds:

| Variable | Value | What |
|---|---|---|
| `VITE_SUGGESTIONS_URL` | `https://activeon-suggestions.idleon.workers.dev` | The Worker's origin; also allowed in the page CSP's `connect-src` ([`_headers`](../../apps/activeon/public/_headers)) |
| `VITE_TURNSTILE_SITE_KEY` | `0x4AAAAAAFZh5dFIi0_6HO68` | Turnstile widget site key (its secret lives only in the Worker) |

```sh
for env in production preview; do
  gh variable set VITE_SUGGESTIONS_URL --env "$env" -R YassSoliman/idleon-forge \
    --body https://activeon-suggestions.idleon.workers.dev
  gh variable set VITE_TURNSTILE_SITE_KEY --env "$env" -R YassSoliman/idleon-forge \
    --body 0x4AAAAAAFZh5dFIi0_6HO68
done
```

Only a production build files real issues. Preview and local builds send the `X-Suggestions-Dry-Run: 1`
header, and the Worker also treats any `pr-<N>-activeon.idleon.workers.dev` origin as a dry run: full
validation, proof and Turnstile checks, a fake issue back, nothing written to GitHub (M13 RT-20). The
Worker's CORS admits only the production origin and the Preview pattern, so a `localhost` build can't
send at all; test the Worker itself with `node workers/suggestions/scripts/smoke.mjs`. Without the two
variables the form still opens, offering the pre-filled GitHub issue instead.

| `ActiveOn` (production) | `production` | Account token, IdleOn only, **Workers Scripts: Edit** | set by Yasser | 11 months after creation |
| `activeon-preview` | `preview` | Account token, IdleOn only, **Workers Scripts: Edit** | 2027-10-17 | 2027-09-17 |

Workers Scripts: Edit is account-wide; the IdleOn account holds only the Forge's Workers, which is the
whole blast radius. Verified 2026-10-17: the production token deploys and the preview token runs
`wrangler preview` (PR #57) with Workers Scripts: Edit alone. Rotation:
[`release.md`](release.md#token-rotation).

## Manual deploy (owner only)

```sh
pnpm build                       # with apps/activeon/.env.local filled in
cd apps/activeon && pnpm exec wrangler deploy   # uses your wrangler login
```

`pnpm exec wrangler deploy --dry-run` validates the config without an account. Prefer merging to
`main`: a manual deploy skips the gates, and the next merge overwrites it anyway.
